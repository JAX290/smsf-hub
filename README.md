# SmsForwarder Hub（短信转发中枢）

把安卓手机上的**短信 / 来电 / APP 通知 / 已发送短信 / 定位**统一收集到自己的服务器，
再**分发到任意多个渠道**，同时自动归档成 Markdown 文件。

配套手机端：[SmsForwarder](https://github.com/pppscn/SmsForwarder)（本仓库是服务端；
改造版的手机端源码脱敏后放在 `android/` 目录，见下文「手机端」一节）。

---

## 为什么需要服务端？

手机直接推送到渠道有几个绕不过去的问题，加一层服务端就都解决了：

| 问题 | 直连渠道 | 经过本服务 |
|---|---|---|
| 企业微信群机器人 **20 条/分钟**限制 | 短信轰炸时丢消息 | 服务端合并窗口攒批发送 |
| 凭据要写进手机 | webhook 泄露风险 | 凭据只在服务器上 |
| 想同时推多个渠道 | 每个渠道配一遍 | 服务端一对多扇出 |
| 想留档 | 要自己另做 | 自动归档 Markdown |
| 想换渠道 | 要改手机配置 | 改服务器配置即可 |
| **网络断了 / 换服务器后没配上** | **消息直接丢** | **存下来，恢复后自动补发** |
| 多台手机混在一起 | 分不清谁是谁 | 按设备分目录、可单独筛选打包 |

## 功能

### 消息类型

| 类型 | 上报路径 | 说明 |
|---|---|---|
| 短信 | `/smsf/hook/sms` | 收到的短信 |
| 来电 | `/smsf/hook/call` | 来电/去电/未接 |
| APP 通知 | `/smsf/hook/notify` | 任意 App 的通知，**用包名标识来源**（中文名由模板变量携带） |
| 已发送 | `/smsf/hook/sent` | **你发出去的**短信（读系统短信库，不需要额外授权） |
| 定位 | `/smsf/hook/location` | 位置变化时上报，带节流（默认 10 分钟或 200 米） |

### 服务端

- **统一入口**：手机只发到一个地址，服务端负责其余一切
- **签名校验**：HMAC-SHA256 + 时间戳时效，拒绝伪造与重放
- **去重**：同样内容短时间内只处理一次（指纹含设备维度，两台手机各自记一份）
- **合并发送**：窗口内的多条消息攒成一条推送，避免刷屏、绕开渠道限流
- **Markdown 归档**：按 `设备/类型/主题/日期.md` 组织，单文件超限自动滚动
- **12 个推送渠道**：企业微信群机器人 / 企业微信应用消息 / 钉钉群机器人 / 飞书群机器人 /
  Telegram / Bark / ntfy / Gotify / PushPlus / Server酱 / 邮件 SMTP / 通用 Webhook
  （另有「仅归档」模式，不推送只留档）
- **控制面板**：总览 / 消息流 / 归档浏览与打包下载 / 终端管理 / 渠道开关 /
  所有参数表单化 / 签名自测
- **消息流三级联动筛选**：终端 → 类型 → 应用，选了一台手机就不会看到它没有的应用
- **多设备**：自动登记每台上报过手机，归档按设备分目录，可单独筛选、单独打包下载
- **换服务器自动配对**：换了 VPS 导致 secret 对不上时，手机能自己恢复（见下文）
- **APK 下载闸门**：下载页可一键开关，关掉后外部访问一律返回「下载未开启」
- **只走内网**：上报入口由 nginx 反代，面板只绑 Tailscale IP，不额外暴露端口

### 手机端（改造版）

在 [SmsForwarder](https://github.com/pppscn/SmsForwarder) 基础上做的改造，
源码脱敏后放在 `android/`：

- **离线待发队列**：发不出去的消息存进数据库，网络恢复 / 每 15 分钟 / 启动时自动重试。
  退避重试（30 秒 → 30 分钟封顶），有次数和保留期上限，不会无限膨胀
- **换服务器自动配对**：上报被拒时自动取回新 secret 并重发，你什么都不用做。
  签名钥匙**从域名派生**，域名不变就自动对得上 —— 换 VPS 不需要传递任何东西
- **定位直接上报**：不再依赖「到达/离开某地址」的自动任务（那个不配就永远不触发）
- **多进程修复**：保活机制会在独立进程再跑一遍 `onCreate`，已加主进程判断，
  避免同一条消息被上报两次
- **权限就绪后锁定设置界面**：短信 / 通话 / 通知使用权 / 定位四类必要权限全部授好后，
  设置界面会自动隐藏、只显示一个绿色对勾，避免误触把权限关掉；
  同时往服务端报一条「【就绪】」消息，你在面板消息流里就能看到这台手机配置完成了
  （长按对勾可临时解锁，退出重进又会锁上）

## 架构

```
[安卓手机] ──HTTPS POST──> [你的服务器]
                              │
                        ┌─────┴─────┐
                        │  smsf-hub │
                        └─────┬─────┘
                              │
        ┌─────────┬───────────┼───────────┬──────────┐
        ▼         ▼           ▼           ▼          ▼
     去重      归档MD      合并窗口    签名校验    多渠道分发
                                              ┌───┴───┬───────┬──────┐
                                              ▼       ▼       ▼      ▼
                                            企微    钉钉    飞书   Bark …
```

- 上报入口：`127.0.0.1:8701`（只给 nginx 反代，公网直接访问不到）
- 控制面板：`<Tailscale IP>:8702`（只有你自己的 tailnet 能打开）

## 部署（Ubuntu 24.04）

### 1. 拉代码

```bash
sudo git clone <本仓库地址> /opt/smsf-hub
cd /opt/smsf-hub
```

### 2. 一键安装

```bash
sudo bash deploy/install.sh
```

脚本会：建虚拟环境 → 装依赖 → 生成 `config.yaml`（含随机 secret 与面板口令）→
装 systemd 服务 → 启动。

**脚本会打印两个值，请记下来：**
- `手机端 secret` —— 填到手机的 SmsForwarder 里
- `面板登录口令` —— 打开面板时用

### 3. 接上 nginx（让公网能上报）

参考 `deploy/nginx-smsf.conf`，把 `location /smsf/hook` 加进你自己的站点配置：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

### 4. 换 VPS 完整步骤

**目标**：把服务端搬到新机器，手机端不用重装、不用改配置。

先给结论 —— 一共四步，其中第 ③ 步最容易漏：

```
① 在新机器上部署服务端           （一条命令 + 回答两个问题）
② 接上 nginx 配置                （把生成的片段贴进去）
③ 在你自己的电脑上把 APK 传上去   （← 最容易漏，漏了下载地址就是空的）
④ 跑环境自检                     （会逐项告诉你哪里没对上）
```

---

#### 第 ① 步：新机器上部署服务端

**先准备一个值**：旧服务器的 `secret`。在旧机器上执行：

```bash
sudo grep -E "secret:|password:" /opt/smsf-hub/config.yaml
```

记下 `secret`（面板口令也一起记下，那个是你自己登录用的）。

**然后在新机器上：**

```bash
sudo git clone <本仓库地址> /opt/smsf-hub
cd /opt/smsf-hub
SMSF_SECRET=<刚才记下的secret> sudo -E bash deploy/install.sh
```

**只需要给 `SMSF_SECRET` 一个值。** 脚本会问你两件事：

| 会问你 | 为什么不能自动 | 想跳过就用环境变量 |
|---|---|---|
| 面板绑哪个 IP | 会自动探测 Tailscale，探不到才问 | `SMSF_HOST=` |
| 上报域名 | 取决于你的 DNS，探测不出来 | `SMSF_DOMAIN=` |

其余全部自动：面板口令（不给就随机）、下载目录（随机名）、**配对钥匙（从域名派生，不用管）**。

> ⚠️ **`pair_key` 不用从旧机器搬**。新版手机用的钥匙是从上报域名派生的 ——
> 域名焊死在 APK 里、换机器不变，所以两边算出来的一定一样。
> 只有手机上装的还是 v41 及以前的旧版时，才需要 `SMSF_PAIR_KEY=<旧钥匙>`（或干脆重装新版 APK）。

---

#### 第 ② 步：接上 nginx 配置

`install.sh` 跑完会生成一个**已经把 IP、端口、随机路径都填好**的片段：

```
/opt/smsf-hub/deploy/nginx-smsf.filled.conf
```

把它里面的 `location` 段加进你自己的 nginx 站点配置，然后：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

这个片段包含四组：

| 路径 | 用途 |
|---|---|
| `/smsf/hook` | 手机上报入口 |
| `/smsf/pair` | 配对接口 |
| `/smsf/panel/` | 面板的归档下载 |
| **`/apk1` `/apk2` `/apk3`** | **安装包下载**（这一步和下一步是配套的）|

---

#### 第 ③ 步：在你自己的电脑上把 APK 传上去

**这一步不能省**，原因很简单：

> **源码仓库里没有 APK** —— 它是编译出来的二进制产物（三个包约 60MB），
> 不适合放进 git。所以新机器上只会有代码，`/apk1` 指向的目录是**空的**。

**APK 存放在你电脑的哪里？**

| 目录 | 里面是什么 |
|---|---|
| `C:\AndroidDev\dist\` | **归档目录** —— 每个版本一个文件，如 `smsf-arm64-v42-3.5.0.260929.apk`。**要备份就备份这个目录** |
| `C:\AndroidDev\SmsForwarder\build\app\outputs\apk\debug\` | 编译产物（每次编译覆盖），上传脚本默认从这里挑最新的 |

**上传指令**（在**你自己的电脑**上跑，不是在服务器上）：

```cmd
cd C:\smsf-hub

set SMSF_PASS=<VPS的root密码>
python deploy\publish_apk.py
```

可选参数：

```cmd
python deploy\publish_apk.py --build     :: 先编译再上传
```

**脚本会自动完成这些事**，你不用填下载目录或域名：

- 从 `deploy/.remote_target`（或环境变量 `SMSF_HOST`）读服务器地址
- 连上后从服务器的 `config.yaml` 读下载目录和上报域名
- 挑出 arm64 / 通用 / 32 位三个包传上去
- 校验远端文件大小、下载地址 HTTP 状态

> **换了一台电脑怎么办？** 把 `C:\AndroidDev\dist\` 整个拷过去即可；
> 或者干脆从旧服务器的下载地址把三个包下载下来备用。
> 另外 `deploy\.remote_target` 也要带过去（或者临时 `set SMSF_HOST=` 指定）。

---

#### 第 ④ 步：自检 + 开闸

```bash
bash deploy/selfcheck.sh
```

它会逐项确认，其中**和下载有关的三项**正是为了防止你漏掉第 ③ 步：

```
[OK]   APK 下载目录存在：/var/www/smsf-dl-xxxxxxxx
[OK]   下载目录里有 3 个安装包
         19.3 MB  smsf-arm64.apk
         22.2 MB  smsf-universal.apk
         19.1 MB  smsf-v7a.apk
[OK]   nginx 片段包含 /apk1（安装包下载地址）
```

**目录空着会直接报「问题」并告诉你怎么办**：

```
[问题] 下载目录是空的！/apk1 会下不到文件。
       在本机跑：python deploy/publish_apk.py
       （源码仓库里没有 APK，它是二进制产物，必须单独上传）
```

最后打开面板 `http://<Tailscale IP>:8702/panel/`，做两件事：

1. **配对栏**点「**开启到真正连上**」—— 等手机自动配对并成功上报一条后，闸门自动关闭
2. 需要下载 APK 时，**下载栏**点一下授权

#### 完整流程一屏版

```bash
# ── 在新 VPS 上 ──
sudo git clone <仓库> /opt/smsf-hub && cd /opt/smsf-hub
SMSF_SECRET=<旧secret> sudo -E bash deploy/install.sh
# 把 deploy/nginx-smsf.filled.conf 里的 location 段贴进站点配置
sudo nginx -t && sudo systemctl reload nginx
bash deploy/selfcheck.sh

# ── 在你自己的电脑上 ──
cd C:\smsf-hub
set SMSF_PASS=<VPS密码>
python deploy\publish_apk.py

# ── 最后 ──
# 面板 → 配对栏 →「开启到真正连上」
# 手机端什么都不用做，会自动重连并把积压的消息补发上来
```

#### 换 VPS 期间手机上的消息会丢吗

**不会。** 手机端有离线待发队列：发不出去的消息存在本地数据库里，
网络恢复、每 15 分钟、以及 App 启动时都会自动重试。
换服务器期间积压的消息，会在重新配对成功后自动补发上来。

#### 完全无人值守的写法

```bash
SMSF_HOST=$(tailscale ip -4) \
SMSF_DOMAIN=notic.example.com \
SMSF_SECRET=<旧secret> \
SMSF_NONINTERACTIVE=1 \
sudo -E bash deploy/install.sh
```

也可以把变量写进 `deploy/install.env`（脚本会自动读，**该文件不进仓库**）。

### 5. 安装包下载：三个地址分别是什么

（**怎么把 APK 传上去**见上一节第 ③ 步，这里只说传上去之后怎么用。）

面板首页点一下「授权」开启下载闸门，然后：

| 地址 | 内容 | 什么时候用 |
|---|---|---|
| `https://你的域名/apk1` | **arm64** | 绝大多数现代手机，体积最小 |
| `https://你的域名/apk2` | 通用包 | `/apk1` 装不上时用 |
| `https://你的域名/apk3` | 32 位（armeabi-v7a）| 老机器 |

三个包是同一份代码的不同架构版本。**闸门关闭时访问会显示「下载未开启」页面**，
这是设计如此（避免安装包被随意抓走）。

> 另外还有个随机的目录形式 `/dl/<随机串>/`，以及短地址 `/apk-<随机串>`，
> 都在 nginx 片段里配好了，平时用不到，知道有这回事即可。

**为什么这一步不能全自动**：APK 在你本地编译，服务器上只有代码。
把三个包（共约 60MB）放进 git 仓库不合适 —— 每次改代码都要带着二进制历史。
所以必须手工触发一次，但**只需要一条命令**。

## 手机端配置

在 SmsForwarder 里新建**发送通道 → Webhook**，按需要建若干条
（分开建服务端才能区分类型）：

| 类型 | WebServer 地址 |
|---|---|
| 短信 | `https://你的域名/smsf/hook/sms` |
| 来电 | `https://你的域名/smsf/hook/call` |
| APP通知 | `https://你的域名/smsf/hook/notify` |
| 已发送 | `https://你的域名/smsf/hook/sent` |
| 定位 | `https://你的域名/smsf/hook/location` |

每条都用同一份配置：

| 字段 | 值 |
|---|---|
| 请求方式 | `POST` |
| secret | 安装脚本打印的那串 |
| headers | `{"Content-Type": "application/json"}` ← **必须** |
| webParams | 见下 |

**webParams（请求体模板）**：

```json
{
  "device": "[device_mark]",
  "from": "[from]",
  "content": "[content]",
  "app": "{{APP_NAME}}",
  "sim": "[title]",
  "app_version": "[app_version]",
  "receive_time": "[receive_time:yyyy-MM-dd HH:mm:ss]",
  "ts": "[timestamp]",
  "sign": "[sign]"
}
```

> - `device` 建议用 `[device_mark]`（APK 首次启动自动生成的稳定 ID，形如 `SF-B7AEFBF931`）。
>   服务端靠它区分不同手机、决定归档目录，**不要填会变的中文备注名**。
> - `app` 只在 APP 通知那条用得上。改造版用 `{{APP_NAME}}` 模板，
>   上报的 `from` 是包名、应用中文名由这个字段携带（服务端会合并两种写法）。
> - 可用变量：`[from]` `[content]` `[msg]` `[org_content]` `[device_mark]`
>   `[app_version]` `[title]` `[card_slot]` `[timestamp]` `[sign]` `[receive_time]`

配好后打开面板的**自测**页，里面有现成的 `curl` 命令，可以先在服务器上验证全链路。

## ⚠️ 注意事项

### 1. 去重窗口不要调太小（和离线补发有关）

`dedup.window_seconds` 默认 **900 秒**。**这不是随便设的。**

手机端有离线补发：失败的消息会存下来，等网络恢复重试，**重试间隔是退避的**
（30 秒起步，最长 10 分钟）。如果去重窗口只有 60 秒：

```
消息其实已经到服务端了，但当时响应超时 → 手机判定为失败
  ↓ 30 分钟后重试
服务端：指纹不在窗口内 → 当成新消息，又记一遍
```

结果就是**消息变多而不是变少**。

指纹里**不含时间戳**（`类型|发件人|应用|内容|设备`），所以放大窗口不会误伤真正不同的消息 ——
900 秒内同一台手机、同一发件人、**完全相同的内容**，几乎只可能是重复上报。

### 2. 签名不覆盖消息内容，必须走 HTTPS

HMAC 签名只保证「这条请求是你发的」，**不保证内容没被改**。
所以上报必须走 HTTPS，否则中间人可以把短信正文改掉。

### 3. 配对闸门默认关闭，换服务器时记得开

换 VPS 时如果 `config.yaml` 没带过去，新服务器会生成不同的 secret，手机怎么发都会被拒。
配对机制能让手机自己恢复：

```
手机发现被拒 → 用签名钥匙问服务器「现在的 secret 是什么」
  → 服务器答（前提：配对闸门是开的）→ 手机自动更新 → 恢复正常
```

- 闸门**默认关闭**，只在换服务器时临时打开
- 面板提供三种开法：**开 N 分钟** / **开到真正连上**（推荐） / **开到取回密钥**
  —— 详见「换 VPS」一节
- 配对接口有频率限制（默认 6 次/分钟）
- 每次配对都写一行记录（时间、设备、来源 IP），可在面板核对

**为什么设计成「开关式」而不是常开**：配对接口是公网可达的。
平时关着意味着就算那把钥匙被人知道了也用不上。

另外，配对**不会更换**服务器的 secret，只是把它下发给能通过校验的手机 ——
所以就算有人蒙混配对成功，他顶多能伪造上报，**没办法把你踢下线**。

### 4. 归档目录第一层是设备 ID，不是备注名

```
app/data/archive/
├── SF-B7AEFBF931/          ← 设备 ID（稳定，不变）
│   ├── 短信/10086/2026-09-29.md
│   ├── APP通知/com.tencent.mm/2026-09-29.md
│   └── 定位/2026-09-29.md   ← subject_rules 为 none，少一层
└── SF-BFDE5FB748/
```

用设备 ID 而不是备注名，是因为备注名你会改（「手机2」→「红米」），
一改就会把同一台机器拆成两组。备注名在面板「终端」页里改，只影响显示。

### 5. 手机端没带 `device` 字段会怎样

服务端退回用**来源 IP** 识别。同一个 WiFi 下的多台手机会被算成一台 —— 已知限制，
所以强烈建议在 webParams 里带上 `[device_mark]`。

### 6. 定位上报有节流，不是实时的

默认「距上次超过 10 分钟」**或**「移动超过 200 米」才上报一次。
另外它用的是**被动定位**（搭其他 App 请求定位的便车），
所以手机一直不动、也没别的 App 在用定位时，可能很长时间没有新位置。

### 7. 手机端装完要手动放行几个系统设置

APP 首次启动会引导，但这些系统页面**不同厂商不一样，没法完全自动跳转**：

- **电池优化 / 后台运行**：要放行，否则会被杀
- **自启动管理**（华为叫「应用启动管理」）：要改成**手动管理**，
  并勾选「开机或后台自启动」。默认的「自动管理」不允许后台自启
- **通知权限**：不开的话前台服务通知不显示

### 8. 换服务器后手机不用重装

**只要手机上装的是 v42 或更新，就真的什么都不用做。** 手机自己会配对、取回新
secret、把断网期间积压的消息补发出去。

密钥不需要你传 —— 它是**从上报域名派生**出来的（域名焊死在 APK 里，换机器不变，
所以两边算出的值自动一致）。完整步骤见上面「换 VPS 怎么办」一节。

如果手机上还是 v41 及以前的旧版，需要把旧 `pair_key` 带过去（或者重装新版 APK）。

## 参数怎么改？

**不用碰代码。** 两种情况：

1. **面板里改**（推荐）：面板 → 参数设置 / 推送渠道 → 表单里改 → 保存 → 重启服务
2. **改配置文件**：编辑 `/opt/smsf-hub/config.yaml`，每行都有中文注释，改完重启

面板保存时会**保留配置文件里的中文注释**（不是整个重写），所以配置始终可读。
可调项见 `config.example.yaml`。

## 安全

- 上报必须带合法 HMAC-SHA256 签名，且时间戳在容忍范围内（默认 300 秒，防重放）
- ⚠️ 签名**不覆盖消息内容** → **必须走 HTTPS**
- `config.yaml` 含凭据，权限 600，已在 `.gitignore` 中
- 归档目录含短信正文，同样不进仓库
- 面板只绑 Tailscale IP，不在公网暴露
- 配对闸门默认关闭 + 频率限制 + 配对日志
